# DegenDNA 参赛实现与验收

## 产品范围
面向希望理解近期状态、行为偏好和自我照顾方法的中文用户。核心体验是匿名自查、具有边界说明的多维解读、可执行建议和本机记录。邮箱账号用于身份与运营管理，不自动同步答案。不能把自编题库包装成临床诊断或经过验证的人格测量。

本次新增：邮箱六位验证码注册/登录、昵称、退出、账号资料导出、再次验证后注销；管理员白名单、用户分页、停用/恢复；公开题库与程序版本清单、浏览器文件一致性核对、独立 DeWEB 静态构建、X Layer 双 RPC 协议预检及发布后逐字节核验工具。

## 账号上线步骤
1. 在本机忽略的 `.env.auth.local` 填写专用项目配置（管理字段兼容新版 sb_secret_ 与旧版 service_role JWT）。Publishable key 可用于公开客户端，service_role 只用于服务器，不能放入 public 或聊天。
2. Supabase 邮件模板使用六位验证码 `{{ .Token }}`。保持邮箱确认开启；配置面向真实用户的 SMTP，检查发信域名认证、限额与退信。默认邮件服务不等于公开运营邮件服务。
3. 用用户指定的测试邮箱发送真实验证码；用户在页面输入验证码。检查错误码、重复发送、登录、刷新、退出和再次登录。不要记录验证码或令牌。
4. 管理员本人完成注册后，将其 auth.users UUID 填入 `AUTH_ADMIN_USER_IDS`。不要自动提升第一个用户，不要依赖用户可修改的 metadata 判断权限。
5. 检查专用 service_role 密钥有效、管理列表可用；用专用测试账号检查停用、恢复和二次验证注销。管理员本人不能从此页面注销或停用。
6. 将必要配置安全导入 Fly secrets，启用 AUTH_ENABLED=true，PUBLIC_SITE_URL=https://degendna.fun。导入过程不得输出密钥。部署后验证 Secure/HttpOnly/SameSite cookies、跨来源拒绝、匿名测评和个人数据未上传。

账号资料与测评资料分离：退出/注销账号不会擦除当前设备本地记录；页面明确说明。运营数据库只有邮箱、昵称、认证时间与状态，不存测评答案。多实例限流不能仅依赖进程内计数，公开运营需同时配置 Supabase 上游限额；如启用 CAPTCHA，须先实现并验证前端挑战组件，不能只打开后端开关。

## TapeOut / DeWEB 发布步骤
固定参考 TapeKit commit 40994bd65baedbda4df72cb0985031a5f082f606。协议配置是版本依据，不是合约安全审计。

1. 运行 npm run build:release 和 npm run build:deweb。dist/deweb 是待上传目录；首页必须位于 index.html。注册与 AI 的外链有离站说明，新窗口打开，不传本地答案。
2. 用官方 HashPort 控制台选择 X Layer 和自己拥有的 processor/circuit，检查实际费用后由用户钱包签署。禁止收集钱包私钥。必须确认上传到链196，不能照搬其他链示例。
3. 上传路径去除开头斜杠；大文件按协议 putFile/appendChunk，单块最多24000字节；设置 fallback=index.html。保留许可证。上传清单包含 release/manifest.json。
4. 用实际 processor index 和 circuit ID 运行：
   node scripts/tapeout/verify-deployment.mjs --processor-index N --circuit-id ID --directory dist/deweb --output docs/accelerator/verified-deployment.json
5. 此命令只读：两个独立 RPC、固定区块、实现地址、容器开通/激活状态、所有公开文件元数据及完整字节均相符才输出 verified。尚未对本产品真实容器执行成功。
6. 在实际 DeWEB 网关独立验收首页、18个模块、三主题、移动端、刷新路由、本地记录隔离与版本核对。只有这些通过后，记录容器地址、链浏览器、网关链接和交易证据。
7. 版本收据 sourceReleaseId 必须对应 DeWEB 清单。网站包和 DeWEB 包构建模式不同，因此 releaseId 不同。不要把 DeWEB 收据冒用为网站包的字节证明。重新构建会将 deployment.json 重置为 not-published，新的发布必须重新核验。

## 参赛与商业验证
新增功能应以活动期间的提交、演示和链上记录证明。提交前复核活动最新规则与截止时间。

首轮招募10名自愿测试者，覆盖新用户、重复使用者、移动端用户；询问结果是否具体、建议是否可执行、边界是否清楚，并记录去标识反馈。没有真实访谈和数据之前，不能虚构留存、付费意愿或满意度。

第一阶段免费匿名体验与可选账号；第二阶段验证付费需求：用户是否愿意为连续复盘工具、更多结构化行动方案或个性化整理付费。付费不得承诺诊断、治疗或投资收益。尚未启用支付、订阅、链上激励或代币。

三分钟演示建议：0:00真实问题与目标用户；0:25完成一项自查并说明特质/优势/代价/建议；1:15匿名与账号分离；1:40公开版本核对及真实 DeWEB 访问（尚未发布时明确展示待发布状态）；2:20用户反馈与商业假设；2:45新增开发和后续里程碑。视频本身尚未制作，链上片段须等真实发布完成。

## 当前认证方案更新：邮箱登录链接
用户决定先使用默认邮件中的登录链接，验证码升级暂停；上文 OTP 模板配置步骤不作为本版本登录前置条件。接口 send 使用 PKCE challenge；专用 /auth/callback.html 接收 code，立即清除地址栏参数并向同源服务器提交。verifier 只在 HttpOnly cookie 中保存，服务端交换并远程验证身份后设置会话。需同一浏览器打开邮件链接；跨浏览器、重复、过期与缺失参数有明确失败提示。账号注销改为10分钟内新链接验证后输入 DELETE，不再要求数字验证码。

Supabase URL Configuration 必须设置 Site URL=https://degendna.fun，并在 Redirect URLs 加入 https://degendna.fun/auth/callback.html。本机真实测试还需 http://127.0.0.1:8794/auth/callback.html。2026-10-16 已回读确认正式域名和两个回跳地址保存正确。随后真实发信返回429；项目当前默认发信额度每小时2封，未配置自有SMTP。真实邮件点击登录仍未通过；不要据隔离测试宣称已上线可用。默认邮件的公开收件范围限制仍存在，后续运营升级邮件服务是独立里程碑。
