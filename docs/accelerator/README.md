## 账号运行与维护
- 专用项目配置在忽略的.env.auth.local，线上用Fly secrets。Publishable key与服务端管理密钥分开，禁止把服务器密钥放进public、截图、仓库。
- 当前使用默认登录邮件，不要求改OTP模板。验证码升级暂停；scripts/configure-auth-email.mjs是未来维护工具，不在登录流程中执行。
- Site URL=https://degendna.fun；回跳允许 https://degendna.fun/auth/callback.html。本机允许http://127.0.0.1:8794/auth/callback.html；测试结束后可移除本机地址。
- 优先PKCE，verifier只在HttpOnly cookie保存；兼容fragment会话时要求签名的同浏览器邮箱申请、远程核验身份并交换刷新令牌。回调立即清理地址参数，不记录凭证。
- 会话cookie生产环境使用Secure、HttpOnly、SameSite=Lax和__Host前缀。每次读取身份由Supabase验证；管理员权限只使用服务端UUID白名单。
- 注销需要10分钟内重新点击邮件链接验证身份，再输入DELETE。管理员本人先移交权限；不会自动删除本机记录或已下载文件。
- 账号资料只有邮箱、昵称、预设头像及认证时间/状态；不上传答案、草稿、报告、日记、Reset，不做跨设备私密记录同步。
- 进程内限流只覆盖当前实例，公开运营还需Supabase上游限流。未实现前端挑战前不得单独打开CAPTCHA后端开关。
- 曾发到聊天的临时管理令牌和服务器密钥应由维护者撤销/轮换；新凭证直接存本机受限文件，避免再次发送。

## TapeOut / DeWEB 发布
参考TapeKit固定commit 40994bd65baedbda4df72cb0985031a5f082f606；协议配置不是独立安全审计。

1. npm run build:release；npm run build:deweb。正式网站包与DeWEB包模式不同，releaseId不同。dist/deweb仅含公开前端、题库和工具，不含认证服务器或任何凭证。
2. 生成上传计划并打包，逐文件核验大小、哈希、MIME和24000字节分块数。文件路径去掉开头斜杠；首页为index.html，设置fallback=index.html。
3. 使用已确认支持X Layer链196的发布入口，选择本人拥有的processor/circuit，确认实际费用后由用户钱包签署。只连钱包，不收集私钥。没有交易前不得填写容器或交易哈希。
4. 上传公开文件及release/manifest.json；账号/AI只提供有离站说明的外链，不自动请求链外服务，不传个人答案。
5. 用真实编号执行：
   node scripts/tapeout/verify-deployment.mjs --processor-index N --circuit-id ID --directory dist/deweb --output docs/accelerator/verified-deployment.json
   命令只读，核验两RPC固定区块、实现、容器状态和全部公开文件字节，完全匹配才输出verified。当前严格命令会因 binding live=false 拒绝出具完整 verified 收据；这是保留的校验门槛，不应绕过。文件字节核验已另有独立证据。
6. 在真实网关验证三主题、18模块、移动端、刷新、独立来源存储和版本核对。链上hash一致不等于内容科学有效。
7. 重新构建将deployment.json重置为not-published；新版本必须重新核验。不要把DeWEB收据冒用为网站包的字节证明。
